# Vision Wormhole + JEPA 防坍塌 — 完整实验设计方案 v2

> 基于小样本预实验：Original Effective Rank = 2.32（严重坍塌），VICReg 0.1→1.89（恶化），VICReg 0.5→5.42（不足），I-JEPA→75.53（根治，32× 提升）

---

## 一、研究故事线

```
Vision Wormhole 声称: UVC 提供"丰富的信息通道"用于异构 VLM 隐空间通信
           ↓
我们发现:       UVC 存在严重维度坍塌（512 维实际只用 2 维）
           ↓
我们提出:       将防坍塌方法引入 codec 训练
           ↓
小样本验证:     VICReg 缓解但不够（eff_rank 2→5）; I-JEPA 根治（eff_rank 2→75）
           ↓
全量训练验证:   坍塌趋势在全量数据上是否复现？（待验证 H5）
           ↓
下游任务验证:   防坍塌是否转化为更好的通信质量？（待验证 H4）
```

**关键：** 故事线最后一步标记为"待验证"，不说"我们证明"。

## 三、Codec 变体设计（4 组）

| 编号 | 名称 | 训练方式 | Loss |
|:---:|------|------|------|
| **M0** | Original（Baseline） | Teacher-student distillation | `1.0×MSE(student_h, teacher_h) + 0.25×KL(student_logits, teacher_logits) + 0.1×MSE(inj_rms, dummy_rms)` |
| **M1** | +VICReg λ=0.1 | 同 M0，加弱正则 | M0 loss + `0.1×(var_loss + cov_loss)` |
| **M2** | +VICReg λ=0.5 | 同 M0，加强正则 | M0 loss + `0.5×(var_loss + cov_loss)` |
| **M3** | +I-JEPA | **两阶段训练**（见下方说明） | Stage 1: `1.0×MSE(pred_U_a, U_b) + 0.1×(var_loss + cov_loss)` |

**M3 训练细节（两阶段）：**

```
Stage 1 (I-JEPA 防坍塌 encoder, ~3.3h):
  anchor + noise_a → encoder → U_a → predictor → pred_U_b
                                            ↓ MSE
  anchor + noise_b → encoder → U_b (stop_grad)

  encoder + predictor 可训练，无 teacher forward，无 decoder

Stage 2 (冻结 encoder, 训练 decoder, ~3.3h):
  encoder (冻结) → U → decoder → delta, gate → 注入 VLM
  同 M0 loss: MSE(student_h, teacher_h) + KL + Stats

  decoder 从头训练，和 M0 decoder 训练量完全一致
```

**为什么 M3 是两阶段？** I-JEPA 的 encoder 学习"在 universal space 中保留多种信息"，但 decoder 仍需要 teacher-student 蒸馏学会"把 U 翻译成有效 VLM 注入"。两阶段解耦了两个目标。对比 M0 单阶段 encoder+decoder 联合训练，M3 的额外成本是 Stage 1 的 3.3h。

**训练参数统一：**
```
vision_codec_dim=512, tokens=1024, img_tokens=256
heads=8, layers=6, dropout=0.10
train_steps=400, batch_size=2, lr=2e-4
latent_steps=1024
```

## 五、完整实验管线（5 阶段，精简版）

### 阶段 1：Codec 训练

```
Model A (Qwen3-VL-2B):

M0_A:  teacher-student                          → codec_qwen3_m0.pt        (~3.3h) ✅ 已有
M1_A:  teacher-student + VICReg λ=0.1           → codec_qwen3_m1.pt        (~3.3h) ✅ 已有
M2_A:  teacher-student + VICReg λ=0.5           → codec_qwen3_m2.pt        (~3.3h) ✅ 已有
M3_A:  I-JEPA encoder → freeze → decoder        → codec_qwen3_m3.pt        (~6.6h) ✅ encoder 已有，缺 decoder

Model B (LFM2.5-VL-1.6B):

M0_B:  teacher-student                          → codec_lfm_m0.pt           (~3.3h) ⏳
M3_B:  I-JEPA encoder → freeze → decoder        → codec_lfm_m3.pt           (~6.6h) ⏳
```

**Model B 只做 M0 + M3**，M1/M2 不需要——小样本已证明 VICReg 权重大小在 Qwen3 上的行为，LFM 只验证最极端对比（Original vs I-JEPA）是否一致。

### 阶段 2：Codec Merge（跨模型对齐）

```
仅 2 组 merge:

M0_A.pt + M0_B.pt  →  M0_merged.pt  (以 Qwen3 为 reference)
M3_A.pt + M3_B.pt  →  M3_merged.pt

```

**为什么只 2 组？** Merge 不是核心贡献。只做 Original vs I-JEPA 两组，验证"防坍塌是否影响跨模型对齐质量"这一关键问题。

**注意：** M3 的 merge 需要 decoder 已训练（阶段 1 M3_A 已完成两阶段）。

### 阶段 3：SVD 坍塌分析

每个 checkpoint 独立分析，指标同小样本实验：

| # | 指标 | 好值范围 | 测量什么 |
|:---:|------|:---:|------|
| 1 | Effective Rank | > 50 | 等价独立维数 |
| 2 | RankMe | > 7 | SSL 表示质量 |
| 3 | SmoothRankMe τ∈{0.5,1,2} | > 8 / > 5 / > 2 | 多尺度平滑熵 |
| 4 | Spectral Gap | < 5× | σₖ/σₖ₊₁ 最大比值 |
| 5 | σ₂/σ₁ ratio | > 0.3 | 第二方向相对强度 |
| 6 | SV Gini | < 0.5 | 奇异值分布均等度 |
| 7 | Token CosSim | < 0.7 | Token 间平均余弦相似度 |
| 8 | Dead Dims | 0 | std < 0.01 的维度数 |

**分析对象（~12 个 checkpoint × 5min = ~1h）：**

| 模型 | M0 | M1 | M2 | M3 | Merge M0 | Merge M3 |
|------|:--:|:--:|:--:|:--:|:--:|:--:|
| Qwen3 (A) | ✅ | ✅ | ✅ | ⏳ | — | — |
| LFM2.5 (B) | ⏳ | — | — | ⏳ | — | — |
| A+B merged | — | — | — | — | ⏳ | ⏳ |

**对比维度：**
1. Qwen3: M0 vs M1 vs M2 vs M3（4 路对比，核心结论）
2. Qwen3 单模型 vs A+B merged（merge 是否加剧坍塌？）
3. Qwen3 M0 vs LFM M0（Dense vs 混合架构，坍塌程度有差异吗？）

### 阶段 4：下游任务评估

| 任务 | 类型 | 指标 | 论文有 Baseline |
|------|------|:---:|:---:|
| GSM8K | 数学推理 | Accuracy | ✓ |
| ARC-Challenge | 科学推理 | Accuracy | ✓ |
| GPQA | 研究生级 QA | Accuracy | ✓ |

**为什么只 3 个任务？** 单卡 3090 跑多 agent pipeline 很慢（4 agent × 1024 latent step）。3 个核心任务足够验证 H4。

**只对比 M0 vs M3（2 组 × 3 任务 = 6 次推理）。** M1/M2 的 SVD 已说明问题，下游没必要全跑。

```
推理: M0_merged.pt vs M3_merged.pt, 每 checkpoint 每任务 ~50 样本

评估: M3 accuracy > M0 accuracy? 
      → 是: "防坍塌改善了通信质量" ✓
      → 持平: "坍塌程度和通信质量解耦，Vision Wormhole 不需要丰富信息通道也能工作"（同样是有趣发现）
      → 否: 需要分析原因（decoder 训练不足？encoder 学到了对通信无用的信息？）
```

**注意：** `run.py` 是多 GPU 管线（论文用 8×GPU）。需确认为单 3090 跑需要什么修改（可能需调小 `GENERATE_BS` 或关掉 partition runner）。

### 阶段 5：消融实验

**保留 3 组（可行且必要）：**

| 消融 | 变化 | 实验数 | 时间 | 验证问题 |
|------|------|:---:|:---:|------|
| **A. anti-collapse λ 网格** | λ ∈ {0.01, 0.05, 0.1, 0.3, 0.5, 1.0} | 6 组 | ~20h | 最优 λ 范围？过强是否损害 MSE/KL？ |
| **B. variance vs covariance** | var only / cov only / var+cov | 3 组 | ~10h | 两项各自贡献多少？哪项是关键？ |
| **E. 数据量消融** | 90 / 300 / 3000 条 | 3 组 | ~10h | 数据多样性本身能防坍塌吗？ |

**为什么删了 C/F/D？**
- C（架构搜素 layers∈{2,4,6,8} + dim∈{256,512,1024}）= 12 组 × 3h = 36h，不在核心贡献链
- D（token 数量 4 变体 × 4 token）= 16 组，时间爆炸
- F（I-JEPA noise std 4 个值）= 13h，默认 0.05 已 work，小样本验证优先

三组消融共 12 个实验，~40h。优先跑 A（最核心），B 和 E 视时间而定。

## 八、风险与缓解

| 风险 | 概率 | 严重性 | 缓解方案 |
|------|:---:|:---:|------|
| M3 decoder 训练后 Eff Rank 反而下降 | 中 | 高 | Decoder 目标（teacher-student）可能重新引入坍塌。如在 Stage 2 中也加弱 VICReg 正则 |
| I-JEPA encoder 学到的信息对 decoder 无用 | 中 | 高 | 信息保留 ≠ 信息有用。Stage 2 验证。如 decoder loss 不降 → 需要重建 encoder-decoder 桥 |
| 下游 M3 < M0（防坍塌牺牲了蒸馏精度） | 中 | 低 | 这是重要发现，不是失败。说明坍塌和通信质量解耦 |
| LFM2.5 训练脚本兼容性 | 中 | 中 | 原文用 Qwen3+Gemma，LFM 可能需要额外适配。先做 5-step 测试 |
| 下游推理需多 GPU，单 3090 不够 | 高 | 中 | 调低 batch size，用 `--OOM_RETRY_LEVELS` 自动降级。或仅报告小规模采样结果（10 sample/task），标注"全量评估待多 GPU 环境" |
| 全量 3000 条 Original 不坍塌（Eff Rank > 50） | 低 | 低 | 说明数据多样性是防坍塌的充分条件。I-JEPA 的价值转为"用小数据达到大数据效果"。H5 仍发布 |
